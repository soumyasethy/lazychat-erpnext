## Bug A — agent-generated Page renders HTML source as visible text

### Observed (Chrome, /app/hello-world)

User typed *"create a hello world website"* in the chat panel. Agent (Haiku 4.5 via Vercel AI Gateway) fired `prepare_create_page` with `title="Hello World"`, `page_name="hello-world"`, and content beginning with `&` — the full payload was entity-encoded HTML (`&lt;header&gt;…`).

The Apply card succeeded ("Applied · create_page"). Loading `/app/hello-world` shows the literal text `<header> <h1>Hello World</h1> <p>Welcome to your first Frappe Page!</p> </header> <main> <section> <h2>About This Page</h2> …` rendered as a paragraph in the page body — NOT as real DOM.

### Root cause

The on-disk files written by the commit handler contain entity-encoded source:

- [`hello_world.html`](../../../../agilitas_code/erpnext/frappe-bench/apps/lazychat_erpnext/lazychat_erpnext/desk_assistant/page/hello_world/hello_world.html) line 1: `&lt;header&gt;`
- [`hello_world.js`](../../../../agilitas_code/erpnext/frappe-bench/apps/lazychat_erpnext/lazychat_erpnext/desk_assistant/page/hello_world/hello_world.js) line 3: `page.main.html("&lt;header&gt;\n  &lt;h1&gt;Hello World&lt;/h1&gt;…")`

When the page boots, `page.main.html()` (jQuery `.html()`) sets `innerHTML` to a string of HTML entities. The browser decodes the entities and displays the result as plain text inside the page main wrapper.

Two things conspired:

1. **Playbook misled the agent.** Both `claude_bridge.py:97-101` and `routerSystemPrompt.ts:147-150` say *"Standard `&amp;` / `&lt;` / `&gt;` / `&apos;` / `&quot;` are fine."* The intent was *"these XML entities are valid for escaping `<`/`>`/`&` when they appear in text content."* The agent read it as *"escape all my HTML markup with these entities."* The HTML validator (`page_validators.py:18` lxml strict-XML wrapped in `<html>...</html>`) doesn't catch this because `<html>&lt;header&gt;</html>` is valid XML — just text.

2. **No defensive sanitizer in the commit handler.** [`tools.py:6720-6736`](../../lazychat_erpnext/desk_assistant/tools.py) writes `payload.get('content')` verbatim to the `.html` file and JSON-encodes it into the JS wrapper.

### Fix

Defense in depth — both the prompt AND the commit handler.

**A1 — playbook clarification (prompt)** in both mirrors:

Rewrite rule #2 with role-explicit wording and an example:

```
2. **HTML entities are for TEXT CONTENT, not tag delimiters.** Use entities
   when escaping characters that would otherwise be confused with markup
   inside text — e.g. `<p>5 &gt; 3</p>` (text "5 > 3") or `<code>&lt;header&gt;</code>`
   (text showing a tag). NEVER write `&lt;header&gt;` when you mean `<header>`
   as a real DOM element.

   Numeric entities for symbols outside XML's set: `&#183;` (·), `&#8212;` (—),
   `&#8594;` (→), `&#8377;` (₹), `&#9650;` (▲), `&#9660;` (▼). Named entities
   like `&middot;` / `&mdash;` are NOT in the XHTML 1.0 set — never use them.

   WRONG: `content: '&lt;header&gt;Hello&lt;/header&gt;'`
   RIGHT: `content: '<header>Hello</header>'`
```

**A2 — defensive sanitizer (commit handler)**:

New helper at top of `tools.py`:

```python
import html as _html_lib
import re as _re_lib

_ENTITY_TAG_RE = _re_lib.compile(r'&lt;[a-z!/]', _re_lib.IGNORECASE)
_REAL_TAG_RE   = _re_lib.compile(r'<[a-z!/]', _re_lib.IGNORECASE)

def _decode_if_fully_entity_escaped(s: str | None) -> str:
    """Defensive: agents sometimes entity-encode their entire HTML output.
    If `s` contains entity-encoded tag starts (&lt;header&gt;) AND zero real
    tags (<header>), unescape it. Mixed content (real tags + intentional
    &lt; for code samples) is left alone — author intent wins.
    """
    if not s:
        return s or ""
    if _ENTITY_TAG_RE.search(s) and not _REAL_TAG_RE.search(s):
        return _html_lib.unescape(s)
    return s
```

Apply to `payload.content` (and `payload.style` / `payload.script` for symmetry — same hallucination class) at TWO call sites:

- [`tools.py:6720`](../../lazychat_erpnext/desk_assistant/tools.py) — `create_page` branch, before building the JS wrapper.
- [`tools.py` Page-special-case in `update_doc` branch](../../lazychat_erpnext/desk_assistant/tools.py) (added in Cycle 13.1) — same pre-write decode.

### Edge cases

| Input | Detect | Action |
|---|---|---|
| `<header>...` (real HTML) | no `&lt;` match | unchanged |
| `&lt;header&gt;...` (pure entity) | `&lt;` match + no `<` match | `html.unescape` |
| `<pre>&lt;tag&gt;</pre>` (mixed: code sample inside real `<pre>`) | both match | unchanged (author intent) |
| `null` / `""` / missing | early return | `""` |

### Tests (in-process smoke `_smoke.py`)

- **T100o** — feed entity-encoded `content="&lt;h1&gt;hi&lt;/h1&gt;"` to `prepare_create_page` + commit; assert disk `.html` file contains `<h1>hi</h1>`, NOT `&lt;h1&gt;hi&lt;/h1&gt;`.
- **T100p** — feed mixed content `"<pre>&lt;header&gt;</pre>"`; assert disk `.html` file contains the original string verbatim (no decode).

## Bug B — Result Ready pill leaks across sessions

### Observed (multi-session chat panel)

User runs a tool in session A that produces an `mcpPreviewAction` with `status='done'`. They scroll the result card off-screen, then switch to session B (or open a new session). The "Result ready ↓" pill appears in session B even though session B has no completed tool dispatch.

### Root cause

`useUI.lastResultMessageId` is a **global** `string | null` field in [`store/ui.ts:128`](../../../../lazychat.ai/apps/chat-ui/src/store/ui.ts#L128). It is shared across all sessions. The writer ([`MCPPreviewActionCard.tsx:248`](../../../../lazychat.ai/apps/chat-ui/src/components/messages/MCPPreviewActionCard.tsx#L248)) records only `msg.id`:

```ts
useEffect(() => {
  if (msg.status !== 'done') return;
  setLastResultMessageId(msg.id);
  ...
}, [msg.status, msg.id, setLastResultMessageId]);
```

The reader ([`ResultReadyPill.tsx:30-55`](../../../../lazychat.ai/apps/chat-ui/src/components/messages/ResultReadyPill.tsx#L30-L55)) sets up an `IntersectionObserver` after `querySelector('[data-msg-id="..."]')`. After session switch, that selector returns null because session A's `MessageList` unmounted; line 36-39 falls into:

```ts
if (!node) {
  setOffScreen(true);  // bug — pill renders pointing at nothing
  return;
}
```

So the pill renders in session B, pointing at a message id that doesn't exist in the current DOM. Click handler harmlessly no-ops (line 64 `if (node)` guards), but the pill is visible and confusing.

### Fix

Make the published value session-scoped at the writer + bail in the reader on session mismatch + clear stale references.

**B1 — widen the type** ([`store/ui.ts`](../../../../lazychat.ai/apps/chat-ui/src/store/ui.ts)):

```ts
// was: lastResultMessageId: string | null;
//      setLastResultMessageId: (id: string | null) => void;
lastResult: { sessionId: string; msgId: string } | null;
setLastResult: (v: { sessionId: string; msgId: string } | null) => void;
```

Rename for clarity (`lastResultMessageId` → `lastResult`). Initial value `null`.

**B2 — writer wraps with active session id** ([`MCPPreviewActionCard.tsx:248`](../../../../lazychat.ai/apps/chat-ui/src/components/messages/MCPPreviewActionCard.tsx#L248)):

```ts
useEffect(() => {
  if (msg.status !== 'done') return;
  const sid = useSessions.getState().activeId;
  if (sid) setLastResult({ sessionId: sid, msgId: msg.id });
  // ...rest unchanged
}, [msg.status, msg.id, setLastResult]);
```

`useSessions` already exists in `store/sessions.ts:11` (`activeId: string | null`).

**B3 — reader bails on mismatch + clears stale node refs** ([`ResultReadyPill.tsx`](../../../../lazychat.ai/apps/chat-ui/src/components/messages/ResultReadyPill.tsx)):

```tsx
const lastResult = useUI((s) => s.lastResult);
const setLastResult = useUI((s) => s.setLastResult);
const activeId = useSessions((s) => s.activeId);

// Early bail — wrong session, never render.
if (!lastResult || lastResult.sessionId !== activeId) return null;

// In the IntersectionObserver useEffect:
const node = document.querySelector(`[data-msg-id="${CSS.escape(lastResult.msgId)}"]`);
if (!node) {
  // Stale pointer — clear instead of leaking a visible pill.
  setLastResult(null);
  return;
}
```

**B4 — cleanup on session deletion** ([`store/sessions.ts`](../../../../lazychat.ai/apps/chat-ui/src/store/sessions.ts) `deleteSession`):

```ts
deleteSession: (id) => {
  // ...existing logic that removes session and re-points activeId...
  // NEW: if lastResult pointed at the deleted session, drop it
  const lr = useUI.getState().lastResult;
  if (lr?.sessionId === id) useUI.getState().setLastResult(null);
  // ...
}
```

### Edge cases

| Scenario | Behavior |
|---|---|
| Result generated in A, user stays in A, scrolls card off-screen | pill renders in A (correct, unchanged) |
| Result in A, user switches to B | pill does NOT render in B (sessionId mismatch) |
| Result in A, user switches to B, then back to A, card still off-screen | pill renders in A (sessionId match again) |
| Result in A, user deletes A | `setLastResult(null)` cleanup, pill never renders |
| 30s auto-clear timer | unchanged — fires regardless of session |
| Card re-enters viewport (IntersectionObserver) | clears `lastResult` (existing behavior preserved) |

### Tests ([`ResultReadyPill.test.tsx`](../../../../lazychat.ai/apps/chat-ui/src/components/messages/__tests__/ResultReadyPill.test.tsx))

Update existing tests for the renamed type. Add:

- **session-mismatch returns null**: set `lastResult={sessionId:'A', msgId:'m1'}`, set `useSessions.activeId='B'`, render pill → assert `container.firstChild === null` (no pill).
- **stale-node clears state**: set `lastResult={sessionId:'A', msgId:'doesnotexist'}`, set `activeId='A'`, render → assert `useUI.getState().lastResult === null` after effect (auto-cleared).

Existing red-green case (sessionId match + node off-screen → pill renders) stays — just adapt to new prop shape.

Add cleanup test in [`sessions.test.ts`](../../../../lazychat.ai/apps/chat-ui/src/store/__tests__/sessions.test.ts):
- Set `lastResult={sessionId:'A', msgId:'m1'}`, call `deleteSession('A')` → assert `useUI.getState().lastResult === null`.
